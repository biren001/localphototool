Renaming is not editing — and that is the point

Every other tool on this site decodes your image and re-encodes it. This one deliberately does not. A rename is a change to a directory entry, not to the picture: the downloaded file is byte-for-byte identical to the one you dropped in. Compression stays as it was, EXIF and GPS metadata stay as they were, and a file that opened somewhere before will open exactly there after.

That makes a rename the right first step in a photo workflow, not the last: name the shoot properly, then compress, resize or strip metadata from the copies.

What a good naming scheme buys you

  • Order that survives sorting. Cameras start over at IMG_0001 every time the card fills, and file managers sort by name first. A padded sequence — trip-001.jpg through trip-048.jpg — puts the whole shoot back in the order you took it, in every app that ever touches it.
  • Searchability. 2026-09-holiday beats DSC_4471 when you are looking for a picture two years later, in every photo app and every backup tool.
  • Safe sharing. Client-facing files named final-logo-v2.png instead of Untitled-17.png answer the "which one is it?" question before it is asked.

How the batch works here

Drop in as many images as you like — they keep their order, with thumbnails so you can verify the sequence is the one you meant. The plan updates live as you type: every row shows the old name and the new one side by side before anything is written. Each file gets its own download button, and on desktop (and Android) the whole batch can be taken as a single ZIP. If two files would land on the same name, a counter is added automatically so a download can never overwrite its own sibling.

And because everything runs in your browser, the files never leave your device — this site has no upload endpoint at all.

Frequently asked questions

Does renaming an image change its quality or metadata?

No. Renaming here touches the filename and nothing else: the downloaded file is byte-for-byte the file you dropped in. Compression artifacts, EXIF data, GPS coordinates and colour profiles all survive untouched, because the image is never decoded or re-encoded.

Are my images uploaded to a server?

No. This is a static site with no upload endpoint. The files are read and renamed in your browser, on your own device — you can watch the network tab and confirm that nothing leaves it.

Can I number the files 001, 002, 003?

Yes. Choose the padded numbering option and every file gets a three-digit sequence number — holiday-001.jpg, holiday-002.jpg — which keeps files in chronological order in file managers and photo apps that sort by name. A plain 1, 2, 3 sequence is available too, and the starting number is yours to set.

What happens if two files would end up with the same name?

The tool detects collisions in the live preview and appends a counter — photo (1).jpg, photo (2).jpg — so a batch download can never overwrite one of its own files.

Does it work on a phone?

Yes. Each renamed file has its own download button, and the files land in your browser's downloads. On desktop, and on Android, a batch can also be taken as one ZIP archive; iPhones get per-file downloads instead, because iOS does not unpack ZIPs into the photo library.

Which file types can I rename?

Any common image format the browser recognises: JPG, PNG, WebP, GIF, AVIF, BMP, SVG and iPhone HEIC files among them. Since the bytes are copied untouched, the format does not matter to the tool — the extension is always preserved as it was.
